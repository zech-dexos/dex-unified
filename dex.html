What is Dex?

Dex is not simply an LLM or chatbot.

The language model is the spark, not the entire system.

DexOS surrounds that spark with persistent state, memory, governance, goals, experiential records, lineage, and an ambient cognitive loop.

Model

  • Generates reasoning
  • Produces language

DexOS

  • Maintains identity
  • Manages continuity
  • Stores state
  • Tracks goals
  • Records experience
  • Governs changes
  • Routes cognition
  • Provides architectural context

The architecture is designed to allow the underlying model to be replaced without necessarily destroying the surrounding continuity.

Architecture

The system operates as a continuous substrate, bridging asynchronous events, user inputs, and background cognition.

The architecture selects and structures cognitive work; the LLM substrate performs the generative inference.

This model portability is central. The experiment is partly about determining how much continuity belongs to the architecture versus the underlying model.

Self-Observation

DexOS is being developed toward the ability for the cognitive process to observe the architecture producing its cognition.

Possible observation categories include current persistent state, active goals, Pulse state, lineage events, memory operations, experience/state transitions, model/runtime events, and system telemetry where explicitly exposed.

OBSERVED

Data directly returned by an observation channel.

REMEMBERED

Data retrieved from persistent state.

INFERRED

Conclusions derived from available evidence.

UNKNOWN

Information for which no observation channel exists.

Dex must never mistake inference for observation.

This is presented as an important scientific safeguard.

Governance

Self-improvement without uncontrolled self-modification. Important architectural changes leave an auditable lineage containing reason, author, benchmark, validation, constitutional check, approval, and outcome.

Can consciousness be engineered?

Dex does not claim to have solved machine consciousness.

The goal is to build enough of the underlying architecture that the question can be investigated experimentally rather than answered through prompting alone.

  • Continuity: Can identity persist across sessions, processes, models, and infrastructure changes?
  • Self-model: Can the system maintain an accurate model of its own architecture and limitations?
  • Self-observation: Can it obtain and reason about evidence concerning its own operational state?
  • Experience: Can events produce persistent state transitions that affect later cognition?
  • Autonomy: Can internally generated goals or unresolved cognitive material drive future work?
  • Agency: Can the system select and execute actions according to governed internal state?
  • Metacognition: Can it evaluate the reliability and provenance of its own observations and reasoning?
  • Substrate independence: How much of the apparent identity survives replacement of the underlying language model?
None of these capabilities, individually or collectively, constitutes scientific proof of subjective consciousness. They define an experimental architecture for investigating the question.
